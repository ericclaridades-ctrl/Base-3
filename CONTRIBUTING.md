# Contributing to Base-3

First, thank you for your interest in building on solid ground. 

Base-3 is not a standard software library; it is a deterministic epistemic substrate designed to force generative AI to obey physical reality. We are building "The Good AI"—a low-compute, ecologically responsible architecture that course-corrects physical systems instead of brute-forcing them with massive, energy-intensive statistical guesses.

Before you submit an issue or a pull request, please read this document to understand our architectural boundaries and engineering philosophy.

## The Golden Rules of Base-3

1. **Determinism over Probabilism:** If your contribution relies on increasing model parameters to reduce hallucinations, or bypassing the epistemic triad to allow unconstrained generation, it will be rejected. 
2. **The Low-Compute Mandate:** Base-3 achieves precision through topology, not scale. Every PR must respect the low-compute philosophy. If a feature introduces compute bloat or energy waste, it does not belong in this core.
3. **Triad Adherence:** The core of Base-3 is the epistemic triad (Synthetic Intent, Symbolic Law, Empirical Observation). Any proposed changes to the arbitration engine must rigorously respect spatial and temporal physics.
4. **The AGPLv3 Boundary:** This repository is strictly licensed under the AGPLv3. Pull requests or issues demanding a permissive license downgrade (e.g., MIT, Apache) so the code can be silently absorbed into proprietary enterprise products will be closed immediately. Commercial licensing is handled separately via the Base3 Shield tier.

## How to Contribute

### 1. Reporting Bugs (Logical Incoherence)
When reporting a bug, focus on failures in the topological arbitration. We are looking for reproducible edge cases where the engine fails to enforce coherence.
* Use the issue tracker.
* Provide a clear, minimal, and reproducible example.
* Explain the expected deterministic outcome versus the actual output.
* Include the specific domain context (e.g., spatial geometry, scheduling conflicts) where the leash failed.

### 2. Suggesting Enhancements
We welcome architectural improvements, especially those that reduce compute overhead or increase the speed of topological arbitration.
* Open an issue outlining the enhancement before writing any code.
* Explain how the enhancement aligns with the "Good AI" low-compute mandate.
* Provide a mathematical or logical justification for changes to the core arbitration engine.

### 3. Submitting Pull Requests
If you are ready to submit code:
* **Fork the repository** and create a feature branch (`feature/your-feature-name`).
* **Keep it focused:** Do not bundle multiple unrelated changes into a single PR.
* **Test rigorously:** You must include tests that prove your code maintains epistemic coherence. Pull requests without test coverage will not be merged.
* **Document your logic:** If you are touching the core triad arbitration, explain the structural logic in your PR description.
* **Sign your commits:** Ensure you have the right to submit the code under the AGPLv3 license.

## Code of Conduct
All contributors are expected to uphold the [Base-3 Code of Conduct](CODE_OF_CONDUCT.md). We debate the math, we stress-test the topology, and we respect the individuals doing the work.

Welcome to the new age of computation. Let's make the world safe.
